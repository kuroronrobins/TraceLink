# 02 現在のアプリ送信データ整理

この資料では、現在のアプリコードから読み取れる「送信し得るデータ」を整理します。ここに書く「確定」は、現在のコードに存在するという意味であり、本番 API 契約として確定したという意味ではありません。

## 現在の upload payload 候補

現行コードの `InventoryUploadPayload` は次の形です。

```json
{
  "sessionId": "4b89806b-1cde-4c8a-b96f-8f7d72fd2016",
  "sentAtEpochMillis": 1712345678901,
  "deviceId": "android-local-device",
  "readerType": "RP902",
  "tags": [
    {
      "epc": "E2806894000040035A1F90A1",
      "firstSeenAtEpochMillis": 1712345600000,
      "lastSeenAtEpochMillis": 1712345660000,
      "readCount": 3
    }
  ]
}
```

## データ項目一覧

| 項目 | 現在の取得元 | 区分 | サーバー向け説明 |
| --- | --- | --- | --- |
| `sessionId` | `DefaultInventoryRepository.sessionIdFactory()` | 確定 | upload 実行時に UUID 文字列を生成します。retry queue の local key にも使っています。 |
| `sentAtEpochMillis` | `clock()` | 確定 | アプリが upload payload を作った時刻です。端末時計に依存します。 |
| `deviceId` | 固定文字列 `"android-local-device"` | 確定だが仮 | 本番では端末識別子へ差し替えが必要です。 |
| `readerType` | 固定文字列 `"RP902"` | 確定 | 現在は RP902 を表す文字列です。 |
| `tags[].epc` | reader tag read | 確定 | RFID タグの識別子です。空文字は session 側で拒否されます。 |
| `tags[].firstSeenAtEpochMillis` | 初回読取時刻 | 確定 | 同一 session 内で初めてその EPC を読んだ時刻です。 |
| `tags[].lastSeenAtEpochMillis` | 最終読取時刻 | 確定 | 同一 session 内で最後にその EPC を読んだ時刻です。 |
| `tags[].readCount` | `InventorySession` | 確定 | 同一 EPC が session 内で読まれた回数です。 |
| reader Bluetooth address | `ReaderSettings.readerBluetoothAddress` | 拡張候補 | 現在 upload payload には入りません。監査や端末識別で必要なら要合意です。 |
| upload retry attempt count | `PendingUpload.attemptCount` | 内部状態 | 現在 upload payload には入りません。サーバーへ送るかは要合意です。 |
| app logs | `AppLogEntry` | 内部状態 | 現在 upload payload には入りません。障害解析で送るなら別 API がよいです。 |

## EPC と重複除去

| 観点 | 現在の仕様 |
| --- | --- |
| 重複除去の範囲 | アプリの 1 inventory session 内 |
| 重複判定キー | 正規化後の EPC 文字列 |
| 正規化 | trim + uppercase |
| 同じ EPC が再読取された場合 | 既存行の `lastSeenAtEpochMillis` と `readCount` を更新 |
| session を clear した後 | 新しい session として再度読み取り可能 |

重要: アプリ側で重複除去済みでも、サーバー側でも重複対策は必要です。理由は retry、通信失敗後の再送、アプリ bug、別端末からの同一データ送信があり得るためです。

## 現在の Upload completed の意味

| 表示 | 現在の意味 |
| --- | --- |
| `UploadState.Completed(sessionId)` | `UploadRepository.upload()` が `UploadResult.Success` を返したという意味 |
| 現在の実装 | `FakeUploadRepository` が non-empty tags なら success を返す |
| 本物サーバー送信成功か | いいえ。現時点では仮実装の成功表示です。 |
| 本番で必要な変更 | HTTP API 実装を持つ `UploadRepository` を追加し、成功レスポンスを `UploadResult.Success` に変換する |

## 将来拡張候補

| 項目 | 区分 | 補足 |
| --- | --- | --- |
| `readerAddress` | 要合意 | Bluetooth MAC を送る場合、個体情報として扱う可能性があります。 |
| `appVersion` | 提案 | 障害解析と互換性確認に有効です。 |
| `operatorId` | 未定 | 認証と業務要件が必要です。 |
| `locationId` | 未定 | 現場・工程・部屋などの概念が必要です。 |
| `serverReceivedAt` | サーバー側裁量 | サーバー受信時刻として DB で付与するのが安全です。 |
| `uploadAttemptId` | 提案 | retry や監査ログを分ける場合に有効です。 |
| `idempotencyKey` | 要合意 | `sessionId` をそのまま使うか、別 key にするか決める必要があります。 |
