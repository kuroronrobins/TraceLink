# 09 用語集

サーバー担当者とアプリ担当者が同じ言葉で話せるように、主要用語をまとめます。

| 用語 | 説明 |
| --- | --- |
| EPC | RFID タグの識別子です。このアプリではタグを区別する主な値です。 |
| inventory session | ひとまとまりの読取作業です。Upload はこの session 単位で行う設計です。 |
| upload | アプリが読み取った session payload を API へ送ることです。 |
| retry queue | upload に失敗した payload をあとで再送するためにアプリ側へ残す場所です。現在は in-memory です。 |
| idempotency | 同じ request が複数回来ても結果が壊れない性質です。retry がある mobile app では重要です。 |
| sessionId | アプリが upload 時に作る session 識別子です。初期案では冪等性キーとして使います。 |
| deviceId | 端末識別子です。現在は仮固定値で、本番採番方法は未定です。 |
| readerType | reader 種別です。現在は `"RP902"` を送る候補です。 |
| readCount | 同じ EPC が同じ session 内で読まれた回数です。 |
| firstSeenAt | その EPC を session 内で最初に読んだ時刻です。 |
| lastSeenAt | その EPC を session 内で最後に読んだ時刻です。 |
| repository | アプリ内で処理をまとめる層です。upload も Repository 経由で実行します。 |
| gateway | 外部機器や外部 SDK とつながる窓口です。RP902 は `ReaderGateway` の内側に隠します。 |
| reader | RFID タグを読む機器またはその抽象です。fake reader と real RP902 reader があります。 |
| vendor SDK | Unitech が提供する RP902 用ライブラリです。アプリの UI や backend には直接出しません。 |
| PostgreSQL | 今回使うことが確定している relational database です。アプリから直接つながず、backend が利用する想定です。 |
| API | アプリと backend の通信窓口です。HTTP + JSON を推奨します。 |
| validation | 受け取った JSON が必要な形式を満たしているか確認することです。 |
| authentication | 誰からの request か確認することです。API key など方式は未定です。 |
| authorization | その request を実行してよい権限があるか確認することです。 |
| unique 制約 | DB 上で同じ値を重複登録できないようにする制約です。`sessionId` や `(session, epc)` に使う案があります。 |
| foreign key | 親子関係を DB で保証する仕組みです。session と tag の関係に使います。 |
| audit log | いつ誰が何をしたか後から追うためのログです。upload attempt の記録が候補です。 |
| HTTP status | API の結果を表す標準的な番号です。例: `201 Created`, `400 Bad Request`, `500 Internal Server Error`。 |
| 409 Conflict | 同じ key だが内容が矛盾する場合などに使う HTTP status です。 |
| serverReceivedAt | サーバーが request を受け取った時刻です。端末時計と別に保存することを推奨します。 |
