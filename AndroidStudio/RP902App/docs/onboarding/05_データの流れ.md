# 05 データの流れ

この資料では、タグデータ、状態データ、ログ、pending write がアプリ内をどう流れるかを説明します。

## タグデータから結果登録まで

```mermaid
sequenceDiagram
    participant Tag as RFID タグ
    participant RP902 as RP902 / fake reader
    participant Gateway as ReaderGateway
    participant Repo as DefaultInventoryRepository
    participant Session as InventorySession
    participant Result as ReadResultRepository
    participant PG as PostgreSQL function
    participant XC as XCgate

    Tag->>RP902: 電波で読まれる
    RP902->>Gateway: ReaderTagRead を emit
    Gateway-->>Repo: tagReads Flow
    Repo->>Session: record(read)
    Session-->>Repo: List<InventoryTag>
    Repo->>Repo: local judgement
    Repo->>Result: register(bundle)
    Result->>PG: read result registration function
    XC->>PG: final result view 参照
```

## 主なデータ型

| データ | 役割 |
| --- | --- |
| `ReaderTagRead` | 1 回読めたという app-owned 読取データ |
| `InventoryTag` | 同じ EPC をまとめた後の session 内データ |
| `ReadResultRegistrationBundle` | PostgreSQL function へ渡す登録単位 |
| `RegistrationState` | 登録操作の状態 |
| `PendingWrite` | 登録失敗後に保留された bundle |

## 状態データの流れ

```mermaid
flowchart LR
    Reader["ReaderGateway.connectionState"] --> Repo["DefaultInventoryRepository.state"]
    Queue["PendingWriteQueue.pendingWrites"] --> Repo
    Logs["EventLogStore.logs"] --> Repo
    Repo --> VM["InventoryViewModel.uiState"]
    VM --> Screen["InventoryScreen / LogsScreen"]

    SettingsRepo["ReaderSettingsRepository.settings"] --> SettingsVM["SettingsViewModel.uiState"]
    RuntimeRepo["ReaderRuntimeStateRepository.runtimeState"] --> SettingsVM
    SettingsVM --> SettingsScreen["SettingsScreen"]
```

重要:

- Repository state が source of truth です。
- UI state は表示しやすく変換した projection です。
- 画面側で勝手に reader 接続状態や登録状態を作らないようにします。

## Pending write の流れ

```mermaid
flowchart TD
    A["結果登録失敗"] --> B["PendingWriteQueue.enqueueFailure"]
    B --> C["pendingWrites StateFlow 更新"]
    C --> D["InventoryRepositoryState.pendingWrites 更新"]
    D --> E["Inventory 画面 Pending writes 件数更新"]
    E --> F["Retry writes 押下"]
    F --> G["DefaultInventoryRepository.retryPendingWrites"]
    G --> H{"再実行成功？"}
    H -- "はい" --> I["queue から remove"]
    H -- "いいえ" --> J["attemptCount / lastErrorMessage 更新"]
```

現在の queue は in-memory です。将来は `PendingWriteQueue` の契約を保ったまま Room などへ差し替えます。
