# 09 変更ガイド

この資料は、今後よくありそうな変更をどこから始めるか、何を壊しやすいかをまとめたものです。

## 新しい画面を追加したいとき

手順:

1. `ui/<newscreen>` フォルダを作る。
2. `NewScreen.kt` と必要なら `NewUiState.kt` / `NewViewModel.kt` を作る。
3. `ui/app/Rp902App.kt` の `AppRoute` に route を追加する。
4. bottom navigation から新画面を表示する。

注意:

- 画面から repository や SDK を直接作らないでください。
- 画面は state と callback を受け取る形にしてください。

## 新しい reader 実装を追加したいとき

手順:

1. `ReaderGateway` を実装する新クラスを `data/reader` 配下へ作る。
2. 必要なら `ReaderGatewayMode` に mode を追加する。
3. `ConfigurableReaderGateway.createGateway()` に切替を追加する。
4. Settings UI に選択肢を追加する。
5. preflight が必要なら `ReaderConnectionPreflight` に追加する。

注意:

- UI や ViewModel に vendor 型を出さないでください。
- fake reader は既定のまま残してください。
- 未確認 API は TODO と adapter boundary に閉じ込めてください。

## upload を本物サーバーに差し替えたいとき

手順:

1. `UploadRepository` を実装する新しい class を `data/upload` に追加する。
2. `InventoryUploadPayload` が backend contract と合うか確認する。
3. `AppContainer` で `FakeUploadRepository` の代わりに新実装を渡す。
4. 失敗時に `UploadResult.Failure` を返すようにする。
5. repository orchestration のテストを追加する。

注意:

- `DefaultInventoryRepository` に HTTP 詳細を直接書かないでください。
- retry queue の仕様を backend と合わせてください。
- 認証情報や URL をコードへ直書きしないでください。

## 設定項目を追加したいとき

手順:

1. app-owned 設定モデルに項目を追加する。
2. repository 契約に更新関数を足す。
3. in-memory 実装を更新する。
4. `SettingsViewModel` で UI state へ投影する。
5. `SettingsScreen` に入力項目を追加する。

注意:

- 画面だけに設定値を持たせると、gateway 側が参照できません。
- 永続化が必要なら DataStore などを導入する前に契約を確認してください。

## RP902 vendor SDK 呼び出しを追加したいとき

手順:

1. Javadoc と vendor sample source で実 API 名を確認する。
2. `docs/architecture/RP902_Integration.md` に確認できた根拠を書く。
3. `RealRp902Gateway` 内だけで呼ぶ。
4. 失敗時は app-owned `ReaderGatewayEvent` と `ReaderConnectionState` に変換する。
5. 実機未確認なら TODO と structured log を残す。

注意:

- API を推測で書かないでください。
- vendor SDK 型を domain/ui に漏らさないでください。
- callback thread が main thread とは限らない前提で防御してください。

## retry queue を永続化したいとき

手順:

1. `UploadRetryQueue` の契約で足りるか確認する。
2. DataStore / Room などの保存方式を選ぶ。
3. `InMemoryUploadRetryQueue` とは別に新実装を作る。
4. `AppContainer` で差し替える。
5. アプリ再起動後の retry テストを追加する。

注意:

- payload schema を変えると過去 queue との互換性が問題になります。
- queue の重複キーは現在 `sessionId` です。

## やってはいけない変更

- Composable から `RP902Reader` や vendor SDK を直接呼ぶ。
- `InventorySession` に Android API を入れる。
- `DefaultInventoryRepository` に vendor SDK 型を返させる。
- fake reader default を理由なく real に変える。
- sample keystore や sample signing config を app に混ぜる。
- vendor SDK の挙動を推測で説明または実装する。
- retry queue や log store を画面内 state だけで管理する。

## 変更前チェックリスト

1. 変更先の責務は合っているか。
2. UI state は domain/data state の projection のままか。
3. vendor 型が UI/domain に漏れていないか。
4. fake mode で動くか。
5. 単体テストできるロジックは domain/data に置いたか。
6. 実機依存部分はログで観測できるか。
7. docs の説明とコードが矛盾しないか。
