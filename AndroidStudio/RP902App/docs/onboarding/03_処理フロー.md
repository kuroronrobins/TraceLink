# 03 処理フロー

この資料では、ユーザー操作ごとに内部処理がどう進むかを説明します。

## 全体フローチャート

```mermaid
flowchart TD
    Launch["アプリ起動"] --> Container["AppContainer が依存を作る"]
    Container --> VM["ViewModel を作る"]
    VM --> UI["Compose 画面を表示"]
    UI --> Settings{"Settings で real を選ぶ？"}
    Settings -- "いいえ" --> Fake["fake reader のまま"]
    Settings -- "はい" --> Preflight["MAC/権限/Bluetooth preflight"]
    Fake --> Inventory["Inventory 操作"]
    Preflight --> Inventory
    Inventory --> Connect["Connect"]
    Connect --> Start["Start"]
    Start --> Read["Tag read"]
    Read --> Upload["Upload"]
    Upload --> Retry{"失敗？"}
    Retry -- "はい" --> Queue["Retry queue に残す"]
    Retry -- "いいえ" --> Done["完了"]
```

## Connect の詳細フロー

```mermaid
flowchart TD
    A["Inventory: Connect 押下"] --> B["InventoryViewModel.connect"]
    B --> C["DefaultInventoryRepository.connect"]
    C --> D["ConfigurableReaderGateway.connect"]
    D --> E{"gateway mode"}
    E -- "Fake" --> F["FakeReaderGateway.connect"]
    E -- "Real RP902" --> G["preflight 確認"]
    G --> H{"接続可能？"}
    H -- "いいえ" --> I["ReaderConnectionState.Error とログ"]
    H -- "はい" --> J["RealRp902Gateway.connect"]
    J --> K["TransportBluetooth / RP902Reader 作成"]
    K --> L["vendor connect 呼び出し"]
    L --> M["vendor state callback で Connected へ"]
```

real mode でも、preflight が失敗したら vendor SDK に進みません。接続できない理由は Settings と Logs の両方で確認できます。

real path は vendor command を worker 側 dispatcher で実行し、UI main thread を塞がないようにしています。

## Tag 読取の詳細フロー

```mermaid
sequenceDiagram
    participant RP902 as RP902 / vendor SDK
    participant Real as RealRp902Gateway
    participant Repo as DefaultInventoryRepository
    participant Session as InventorySession
    participant VM as InventoryViewModel
    participant UI as InventoryScreen

    RP902->>Real: onRfidUhfReadTag(rawTag, params)
    Real->>Real: raw payload を安全に検査
    Real->>Real: ReaderTagRead へ変換
    Real-->>Repo: tagReads Flow
    Repo->>Session: record(read)
    Session-->>Repo: 重複除去後 tags
    Repo-->>VM: InventoryRepositoryState 更新
    VM-->>UI: InventoryUiState 更新
```

重要:

- callback は vendor SDK 側から来る通知です。アプリ側から呼ぶものではありません。
- 空 EPC や大きすぎる EPC は、アプリ全体を落とさずログ付きで無視します。
- 同一 EPC は `InventorySession` で 1 件にまとめ、`readCount` を増やします。

## Disconnect の詳細フロー

```mermaid
flowchart TD
    A["Disconnect 押下"] --> B["DefaultInventoryRepository.disconnect"]
    B --> C["ReaderGateway.disconnect"]
    C --> D{"Real RP902?"}
    D -- "いいえ" --> E["Fake inventory job 停止"]
    D -- "はい" --> F["stopInventoryOnCommandThread"]
    F --> G["UHF listener detach"]
    G --> H["reader.clearListener / disconnect"]
    E --> I["connectionState=Disconnected"]
    H --> I
    I --> J["Inventory stopped by disconnect ログ"]
```

## 異常時のフロー

| 異常 | 主な検出場所 | どう扱うか |
| --- | --- | --- |
| MAC 未設定 | `ReaderConnectionPreflight` | 接続前に止め、Settings/Logs に理由を出す |
| 権限不足 | `ReaderConnectionPreflight` | vendor SDK 呼び出し前に止める |
| Bluetooth 無効 | `ReaderConnectionPreflight` | Bluetooth settings へ誘導 |
| vendor connect 失敗 | `RealRp902Gateway.connect` | `ReaderConnectionState.Error` とログ |
| tag callback の raw EPC が空 | `Rp902TagEventMapper` | Warning log を出して無視 |
| upload 失敗 | `DefaultInventoryRepository` | retry queue に保存 |
| repository command 例外 | `runReaderCommand` | Error log に残す |
