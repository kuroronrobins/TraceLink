# 04 クラス責務一覧

この資料は、主要クラスごとに「何を担当するか」「何を担当しないか」「どこから呼ばれるか」「修正時の注意点」をまとめたものです。

## 入口と依存関係

| クラス | 担当すること | 担当しないこと | 呼ばれる場所 | 呼ぶ相手 | 修正時の注意 |
| --- | --- | --- | --- | --- | --- |
| `MainActivity` | Android 起動点、`AppContainer` と ViewModel を作り Compose を表示 | 業務ロジック、reader 操作 | Android framework | `AppContainer`, `Rp902App` | ここに処理を増やしすぎない |
| `AppContainer` | アプリ内依存を手動で組み立てる | 画面表示、実処理の詳細 | `MainActivity` | repository / gateway / settings repos | fake default の起点。実装差し替えはここから追う |

## UI と ViewModel

| クラス | 担当すること | 担当しないこと | 呼ばれる場所 | 呼ぶ相手 | 修正時の注意 |
| --- | --- | --- | --- | --- | --- |
| `Rp902App` | 3 画面の切替、権限 launcher、Bluetooth settings 起動 | reader / upload の実処理 | `MainActivity` | `InventoryScreen`, `LogsScreen`, `SettingsScreen` | Android 権限 UI はここ、判定ロジックは domain/data 側 |
| `InventoryScreen` | Inventory 画面表示、ボタン callback 通知 | 重複除去、upload 判断、reader SDK 呼び出し | `Rp902App` | callback 関数 | UI state 以外を独自に持たない |
| `InventoryViewModel` | repository state を `InventoryUiState` に変換、操作を repository に渡す | vendor SDK 呼び出し、重複除去 | `Rp902App` | `InventoryRepository` | UI state は projection のまま保つ |
| `SettingsScreen` | reader mode / MAC / preflight 表示 | 権限の意味判定、接続実行 | `Rp902App` | callback 関数 | 設定の保存先を画面内に持たない |
| `SettingsViewModel` | settings/runtime state を `SettingsUiState` に変換、MAC 入力を検証 | real RP902 接続、vendor API 呼び出し | `Rp902App` | `ReaderSettingsRepository`, `ReaderRuntimeStateRepository` | Android 権限文字列の変換は mapper 経由 |
| `LogsScreen` | 構造化ログ一覧の表示 | ログ生成、ログ保存 | `Rp902App` | なし | ログの意味づけは repository/gateway 側 |

## Inventory と状態管理

| クラス | 担当すること | 担当しないこと | 呼ばれる場所 | 呼ぶ相手 | 修正時の注意 |
| --- | --- | --- | --- | --- | --- |
| `InventoryRepository` | Inventory 機能の app-owned 契約 | 実装詳細 | ViewModel | なし | UI はこの契約だけを見る |
| `DefaultInventoryRepository` | reader events、重複除去、upload、retry queue、log を組み合わせる | vendor SDK 詳細、Compose 表示 | `InventoryViewModel` | `ReaderGateway`, `InventorySession`, `UploadRepository`, `UploadRetryQueue`, `EventLogStore` | 責務が増えたら reader/upload/log 契約へ分ける |
| `InventorySession` | 同一セッション内 EPC の正規化と重複除去 | reader 接続、upload transport | `DefaultInventoryRepository` | なし | 純粋ロジックなので Android 依存を入れない |
| `InventoryTag` | 画面と upload で使うタグ集約モデル | callback raw data の解釈 | `InventorySession` | なし | `readCount` の意味を変えると upload も影響する |

## Reader 周辺

| クラス | 担当すること | 担当しないこと | 呼ばれる場所 | 呼ぶ相手 | 修正時の注意 |
| --- | --- | --- | --- | --- | --- |
| `ReaderGateway` | reader 操作の共通契約 | fake/real の実装詳細 | `DefaultInventoryRepository` | なし | UI/domain へ vendor 型を出さない |
| `ConfigurableReaderGateway` | `ReaderSettings` に応じて fake/real を切り替える | vendor API 直接操作の詳細 | `DefaultInventoryRepository` | `FakeReaderGateway`, `RealRp902Gateway` | mode 切替時は前 gateway を止める |
| `FakeReaderGateway` | 実機なしで接続と tag read を模擬する | vendor SDK 呼び出し | `ConfigurableReaderGateway` | なし | fake default を壊すと開発とテストが難しくなる |
| `RealRp902Gateway` | Unitech SDK を `ReaderGateway` に変換する adapter | UI 表示、upload | `ConfigurableReaderGateway` | Unitech SDK | SDK API は確認済みだけ使う。callback/thread/例外を防御する |
| `DisplayOutputSuppressingRp902Reader` | vendor の `setDisplayOutput` JNI crash 経路を adapter 内で抑止 | reader 全体の代替実装 | `RealRp902Gateway` | `RP902Reader` | workaround なので SDK 更新時に見直す |
| `Rp902TagEventMapper` | vendor tag callback の raw 値を app の `ReaderTagRead` へ安全変換 | repository 更新 | `RealRp902Gateway` | なし | 変換不能でも例外を外へ漏らさない |

## Settings / Preflight

| クラス | 担当すること | 担当しないこと | 呼ばれる場所 | 呼ぶ相手 | 修正時の注意 |
| --- | --- | --- | --- | --- | --- |
| `ReaderSettings` | reader mode と MAC address の状態 | Android 権限状態 | settings/gateway | なし | gateway mode default は fake。MAC default は今回運用の `DC:0D:30:DA:0F:3C` |
| `ReaderSettingsRepository` | settings state の契約 | 永続化方式の固定 | ViewModel/gateway | なし | 現在は in-memory 実装 |
| `InMemoryReaderSettingsRepository` | in-memory settings 保存 | 永続保存 | `AppContainer` | なし | DataStore 導入時も契約は保つ |
| `ReaderConnectionPreflight` | real 接続前の不足条件を判定 | Android UI 表示 | `SettingsViewModel`, `ConfigurableReaderGateway` | なし | 純粋関数なので単体テストしやすく保つ |
| `AndroidReaderPermissionMapper` | app-owned 権限 enum と Android manifest permission の変換 | preflight 判定 | `SettingsViewModel` | Android `Manifest.permission` | domain に Android 文字列を漏らさない |
| `AndroidBluetoothStatusReader` | Bluetooth adapter 状態を読む | 権限要求 | `Rp902App` | Android Bluetooth API | `SecurityException` を状態に変換する |
| `ReaderRuntimeStateRepository` | 権限/Bluetooth 状態 snapshot の契約 | 実機接続 | ViewModel/gateway | なし | 状態は app-owned に保つ |

## Upload / Log

| クラス | 担当すること | 担当しないこと | 呼ばれる場所 | 呼ぶ相手 | 修正時の注意 |
| --- | --- | --- | --- | --- | --- |
| `UploadRepository` | upload transport の契約 | retry queue 管理 | `DefaultInventoryRepository` | なし | 本物 backend は新実装として追加 |
| `FakeUploadRepository` | fake upload 結果を返す | HTTP 通信 | `DefaultInventoryRepository` | なし | backend 未確定の間の仮実装 |
| `UploadRetryQueue` | 送信失敗 payload の再送待ち契約 | upload 実行 | `DefaultInventoryRepository` | なし | 永続化差し替え点 |
| `InMemoryUploadRetryQueue` | in-memory retry queue | 永続保存 | `DefaultInventoryRepository` | なし | アプリ再起動で消える点に注意 |
| `EventLogStore` | 構造化ログ保存契約 | ログ文言生成 | repository/gateway | なし | 表示形式は UI 側 |
| `InMemoryEventLogStore` | in-memory log 保存 | ファイル出力 | `DefaultInventoryRepository` | なし | 最大件数で古いログを捨てる |
| `AppLogEntry` | ログ 1 件の構造 | 表示レイアウト | log store/UI | なし | level/category を増やすと UI 表示も確認する |
